# 国际化（i18n）与翻译

站点默认中文（根路径），英文位于 `/en/` 前缀下。语言工具的唯一来源是
`src/lib/i18n.ts`。

## 英文内容：同目录孪生文件

英文内容以**同目录孪生文件**提供：把中文文件加 `.en.md` 后缀即为英文版：

```
src/content/blog/welcome/index.md      ↔  src/content/blog/welcome/index.en.md
src/content/blog/v1-posts/index.md     ↔  src/content/blog/v1-posts/index.en.md
```

- 内容 id 会保留 `.en` 标记：`v1-posts/index.en.md` → `v1-posts.en`。blog loader 使用
  自定义 `generateId`（`generateBlogEntryId`）实现——默认 glob loader 会吞掉 `.en`
  中的点。
- 图片等资产中英共用，无需复制。
- 机器翻译产物在 frontmatter 标 `aiTranslated: true`，文章页按当前语言显示「AI 翻译」
  （zh）/「AI-translated」（en）徽章；手写 `.en.md` 同样有效。

## UI 文案字典

`UI_STRINGS` 收录界面文案，按 `t(locale, key)` 取用；`zh` 为键名来源，`en` 会检查
完整键覆盖。新增界面文字需同时补 `zh` 与 `en` 两份。

## 未翻译内容在 /en/ 下的呈现

- **列表页**收录全部已发布文章：未翻译条目显示中文原标题并附「Not translated yet」
  徽章；已翻译条目显示英文标题。
- **无译文的文章 URL**（`/en/blog/<id>`）渲染提示页：`noindex`、canonical 指回中文
  原文，并提供回链。
- **系列**中未翻译的子文章在英文系列页渲染占位锚点，其独立 URL 渲染所属系列页；
  仅当整个系列均无任何已翻译节点时，该系列全部 URL（父与子）才统一渲染提示页。
- `draft` 与 `_` 前缀语义沿用中文侧规则；英文孪生条目为 draft 时按「未翻译」处理。

## 语言工具函数

| 函数                          | 作用                                                       |
| ----------------------------- | ---------------------------------------------------------- |
| `localeOf(id)` / `baseId(id)` | 解析内容 id 的语言与基础 id（中英配对键）                  |
| `localeFromPath(pathname)`    | 由站点路径判定语言（`/en` 前缀 → en）                      |
| `localePath(path, locale)`    | 为站点路径加 `/en` 前缀（`/en/blog` ↔ `/blog`）            |
| `stripLocalePath(pathname)`   | 剥离路径的 locale 前缀（`/en/blog` → `/blog`，`/en` → `/`）|
| `t(locale, key)`              | 取界面文案                                                 |

## 翻译脚本

```bash
npm run translate -- <文件或系列目录> [--to en] [--force] [--dry-run]
```

- 读取 `.env` 的 `TRANSLATE_*`（模板见 `.env.example`）：

  ```bash
  TRANSLATE_BASE_URL=   # 任意 OpenAI 兼容端点的基地址（DeepSeek/OpenAI/…）
  TRANSLATE_API_KEY=
  TRANSLATE_MODEL=
  ```

- 保结构翻译（分块进行、带已译上下文链），写盘前做结构校验；失败译文与差异清单落
  `.translate/`（已 gitignore）。
- 无 draft 门禁：`git diff` 即审校；译文自动标 `aiTranslated: true`。
- `--force` 覆盖已有译文；`--dry-run` 只列出计划。

## dev 翻译按钮

`astro dev` 下，中文文章页右下角有「翻译成英文」浮动按钮（模式同 Moment Composer，
生产构建零痕迹）：

- 点击实时检测译文状态：无译文给「生成」；已有译文给「继续（跳过已有）」「全部覆盖」
  「查看」。
- 系列按整组、独立文章按单篇执行；经 dev 端点 spawn `scripts/translate.mjs`，
  进度在终端可见。
- 内容根默认 `src/content/blog/`，可用 `TRANSLATE_DEV_CONTENT_ROOT` 覆盖（测试隔离用）。

## 回归测试

修改 i18n 相关代码后必须全绿：

- `bash scripts/tests/i18n-check.sh` —— 构建后对 `dist/` 逐条断言（中文基线、英文路由、
  未翻译呈现、切换器、SEO/RSS/sitemap）。
- `bash scripts/tests/translate-check.sh` —— 翻译脚本离线桩覆盖（发现/分块/校验/重试
  等路径，无需真实 API key）。
- `bash scripts/tests/translate-ui-check.sh` —— dev 翻译按钮回归。
