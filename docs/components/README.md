# 组件用法文档

这里收录**可复用 / 交互组件**的用法说明，面向后续改代码的人和接手任务的 AI。
每个组件一篇，放在本目录下，文件名用组件的 kebab-case（如 `eye-tracker.md`）。

与其它文档的分工：

- `docs/guides/` —— 面向内容作者 / 部署者的横切主题（写作、i18n、配色、部署）。
- `docs/superpowers/specs`、`docs/superpowers/plans` —— 某次改动的**设计 / 规划**快照，
  讲「当初为什么这么做」，不作为日常用法参考。
- `docs/components/`（本目录） —— 组件**当前怎么用**的实操参考，讲「现在该怎么用」。

## 收录范围

「交互 / 自主组件」指需要 import 到页面（`.astro`）里使用的组件，尤其是遵循
**SSR 静态内容 + 客户端交互激活** 范式的自主定制元素（如把第三方组件移植成本站
`customElements`）。纯展示、无 props 约定的一次性片段不必单列。

## 每篇文档的固定结构

新增组件文档请沿用同一小节顺序，方便人和 AI 快速定位：

1. **一句话说明** —— 组件是什么、给谁看。
2. **文件位置** —— 组件、逻辑模块、样式各在哪，以及样式在哪被全局引入。
3. **快速上手** —— `import` + 最小可用标签示例。
4. **Props** —— 表格：名称、类型/取值、默认值、范围与含义。
5. **模式 / 取值详解** —— 关键属性（如图形形状、眼型）与不同使用模式。
6. **无障碍与降级** —— `role`/`aria-*`、`prefers-reduced-motion`、无 JS 时的静态表现。
7. **注意事项** —— 双语孪生页、跟随/触发范围、与站点令牌（配色）的关系等易踩点。
8. **完整示例** —— 一段可直接参考的真实用法。
