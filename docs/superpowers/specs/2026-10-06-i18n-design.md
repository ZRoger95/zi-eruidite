# 中英双语博客（i18n）设计（中文默认 + AI 翻译管线）

日期：2026-10-06
状态：已批准（2026-10-06，用户逐节审阅 + 全文审查通过）

## 背景与目标

站点是 Astro 静态博客（astro-erudite v2 基底），当前内容与界面文案均为英文。作者希望：

- 用中文写作博客，通过本机脚本调用 AI 生成英文译文（默认目标语言 en，预留 `--to`）；
- 站点提供中英切换（"先做中英文对照"），中文为默认语言；
- AI 服务信息配置在 `.env`。

成功标准：

1. 读者可在中英版本间切换；语言由 URL 决定，产物纯静态、无运行时依赖；
2. 未翻译内容有明确呈现（列表标记 + 提示页 + 系列占位块），不出现死路；
3. 作者一条命令可翻译单篇或整个系列，结果经 `git diff` 审校后随构建发布；
4. 构建过程不调用 AI，部署流程（hexo 式）不变。

## 范围

**覆盖：**

- i18n 基础：locale 工具与文案字典、`/en/` 路由（首页、博客列表、文章/系列）、语言切换器；
- 博客双版内容：`.en.md` 文件约定、内容工具层 locale 化、未翻译标记与提示页、系列占位块；
- 界面文案中英双语（含 zh-only 板块页面文案的字典化）；
- SEO 与输出：canonical/hreflang、sitemap i18n、英文 RSS；
- 翻译脚本（阶段二）：OpenAI 兼容接口、保结构翻译、写盘前结构校验、系列整组翻译；
- 文档与配置：`AGENTS.md` 增补 i18n 约定、`.env.example` 增补 `TRANSLATE_*`、
  `package.json` 增 `translate`。

**不覆盖（本期）：**

- 动态/项目/作者/标签的**内容翻译**与 en 路由（仅做界面文案字典化）；
- 多语言扩展的实装（只保留结构：`.<lang>.md` 后缀与 `--to` 参数位）；
- 术语表文件、翻译质量自动评测；
- 现有英文演示内容的清理或迁移（由作者后续自行替换）；
- 404 页双语化。

## 设计决策（已逐项确认）

| # | 决策点 | 结论 |
| - | - | - |
| 1 | 双语范围 | 界面文案 + 博客文章；动态/项目/作者/标签暂不做 |
| 2 | 默认语言 | 中文（根路径）；英文（`/en/` 前缀） |
| 3 | URL 结构 | 中文保持现有 URL 不变；英文 slug 与中文一一对应 |
| 4 | 未翻译处理 | en 列表全收录 + "未翻译"标记；点击/直达 → 提示页（附中文原文链接）；zh 侧切换器同样指向提示页 |
| 5 | 译文存储 | 同目录 `.en.md` 孪生文件、单一集合；不复制资产（图片相对路径共用） |
| 6 | AI 接口 | OpenAI 兼容：`TRANSLATE_BASE_URL` / `TRANSLATE_API_KEY` / `TRANSLATE_MODEL` |
| 7 | en 导航 | 保留全部 5 项、英文标签；暂不双语板块指向现有中文页面 |
| 8 | AI 标识 | 译文文章页显示"AI 翻译"徽章；frontmatter `aiTranslated: true` 由脚本写入；列表卡片不显示 |
| 9 | 实施顺序 | 阶段一：i18n 框架；阶段二：翻译脚本 |

## 术语与约定

- **Locale**：`zh`（默认）/ `en`；结构上可扩展更多语言。
- **`.en.md`**：英文译文文件命名（后缀插在 `.md` 前），与源文件同目录。blog loader 需自定义
  `generateId`：默认规则会吃掉 `.en` 的点（实测 `rehype-patch.en` → `rehype-patchen`、
  `index.en` → `indexen`），自定义规则先剥离 `.en`、复刻默认 slug（逐段 githubSlug、末尾
  `/index` 归一）后回填 `.en`，得到 id 如 `v1-posts/rehype-patch.en`、父文章 `introducing-v2.en`；
  其余集合沿用默认规则、不受影响。
- **baseId**：剥离 `.en` 后缀的 id，是中英配对键（如 `introducing-v2`）。
- **系列**：`index.md` + 同级子文章目录（现状），只支持一层嵌套。
- **draft 语义**：zh/en 各自沿用现有 `draft: true` 与 `_` 前缀规则；`_` 前缀仅用于中文
  草稿，翻译脚本拒绝翻译 `_` 开头的文件；en 条目为 draft 时按"未翻译"对待。
- **语言派生**：语言完全由文件名 `.en` 后缀派生（单一事实来源），不写入 frontmatter。
- 命名冲突提醒：中文侧文件名不要以 `.en` 结尾。

## 架构设计

### 语言与 URL

- zh（现有不动）：`/`、`/blog`、`/blog/[...id]`、`/moments`、`/projects`、`/authors`、
  `/tags`、`/rss.xml`。
- en（新增）：`/en/`、`/en/blog`、`/en/blog/[...id]`、`/en/rss.xml`。
- 组件内当前语言通过 `localeFromPath(Astro.url.pathname)`（以 `/en` 开头判定）获取，
  避免层层传参；数据查询由页面显式传 locale。

### `src/lib/i18n.ts`（新增）

- `LOCALES = ["zh", "en"]`、`DEFAULT_LOCALE = "zh"`、`Locale` 类型；
- `localeOf(id)`（末段 `.en` 结尾 → en）、`baseId(id)`（剥离 `.en`）；
- `localePath(path, locale)`、`localeFromPath(pathname)`；
- `t(locale, key)` 与文案字典（键清单见「界面与交互」）；
- 站点级按语言元数据：`zh → zh-CN / zh_CN`，`en → en / en_US`（html lang、og:locale）。

### 内容模型（`src/content.config.ts`）

- blog schema 保持现有字段，新增可选 `aiTranslated: z.boolean().optional()`；
- blog loader 自定义 `generateId`（实现为 `src/lib/i18n.ts` 的纯函数）：先剥离 `.en` 语言标记，
  复刻默认 slug 规则（逐段 githubSlug、末尾 `/index` 归一）后回填标记，保证中英孪生 id 配对、
  且中文侧 id 与现状完全一致；
- 原始 md 文件结构不变，仅新增孪生 `.en.md` 文件；图片相对路径 `./assets/*` 天然共用。

### 内容工具层（`src/lib/content.ts`、`src/lib/utils.ts`）

- `getPosts(locale)`：
  - zh：现有行为（排除 draft、排除 `.en` 文件、排除子文章、按日期倒序）；
  - en：以 zh 源集为骨架逐篇配对 `.en` 孪生（需非 draft），返回展示视图
    `{ id, data, translated }`——`data` 取 en ?? zh，供列表卡片与 RSS 使用。
- `getSubposts(locale)`：同构映射；en 系列的渲染链以 zh 结构为骨架，未翻译节点渲染占位块。
- `formatDate(date, locale)`：zh → `2026年6月6日`（Intl `zh-CN`）；en → 现状
  `Jun 6, 2026`（`en-US`）。
- 系列判定（id 段数）不变；slug 工具新增 `.en` 剥离。

### 路由行为

- `/en/blog/[...id]`：为每篇 base 文章（及系列子文章）生成路由：
  - 已翻译（en 条目非 draft）→ 正常文章/系列页；
  - 未翻译（独立文章）→ 提示页（`noindex, follow`，canonical → 中文原文）；
  - 未翻译（系列内子文章）→ 所属系列页中的占位块，该锚点 URL 仍有效；
  - 整个系列无任何已翻译节点时，该系列全部 URL（父与子）统一渲染提示页。
- `/en/blog`：全收录 + "未翻译"标记；`/en/`：最新 5 篇（同策略）。
- 面包屑、目录、上下篇导航均按当前语言构建（en 侧用英文数据与 `/en/` 链接）。

### 数据流

构建时静态生成：路由传入 locale → Layout（`<html lang>`）→ 组件（文案、日期、链接前缀）。
无运行时依赖；构建不调用 AI。

## 界面与交互

### 文案字典（`t(locale, key)`）

初稿键（实现时枚举补全）：导航 5 项、跳过链接、主题切换、全宽切换、上下篇、回到顶部、
目录、列表页标题（"博客"/"Blog"）、RSS 标题、未翻译徽章 / 提示页文案 / 阅读原文按钮、
AI 翻译徽章。zh-only 板块页面文案一并中文化；首页 hero 文案迁到 `consts.ts` 的按语言
结构（只搭结构，不改措辞）。

导航 href 按 locale 展开：博客 → `/en/blog`；暂不双语板块在 en 模式下仍指向中文路径。

### 语言切换器（`LanguageSwitch.astro` 新增）

- 位置：sidebar 布局放侧栏底部（与 ThemeToggle 同区）；topbar 布局放右上操作区。
- 形态：显示**目标语言**（zh 页 "EN"，en 页 "中文"）；带 `lang` 属性与 aria-label。
- 显隐：仅出现在有英文对应路由的页面（`/` ↔ `/en/`、`/blog` ↔ `/en/blog`、
  文章页 ↔ `/en/blog/<id>`）；zh-only 板块页面不显示。
- 无浏览器语言自动跳转、无 localStorage 记忆——URL 即语言状态，默认中文。

### 未翻译呈现

- en 列表/首页卡片：`Not translated yet` 徽章 + 中文原文标题/描述；链接指向提示页。
- 提示页（复用 `MetaPage`，`noindex`）：中文原标题 + "This article hasn't been translated
  yet." + "Read the Chinese original →"（链接 `/blog/<id>`）；canonical 指向中文原文。
- 系列页内未翻译节点：同文案的占位块，保证连续文档不断档。

### 日期与 head

- `<html lang>`：`zh-CN` / `en`；og:locale：`zh_CN` / `en_US`。
- `MetaHead` RSS alternate 链接按当前语言指向 `/rss.xml` 或 `/en/rss.xml`。
- `MetaPage` 增加 canonical 覆盖能力（提示页使用）。

## 翻译脚本（阶段二）

### 命令与入口

- 新增 `scripts/translate.mjs`；`package.json` 增 `"translate": "node scripts/translate.mjs"`。
- 零第三方依赖（Node 原生 fetch）；终端输出中文。
- 用法：

  ```
  npm run translate -- src/content/blog/my-post.md
  npm run translate -- src/content/blog/my-series/index.md   # 系列整组
  npm run translate -- src/content/blog/my-post.md --to en --force
  ```

- 选项：`--to en`（默认 en；参数位留给未来语言）、`--force`（覆盖已有译文；默认逐文件
  跳过并提示）、`--dry-run`（只列计划、不调 API）。
- 输入为系列 `index.md`（或含 `index.md` 的目录）时识别为系列：翻译 `index` 与全部
  非 `_` 子文章，整组共享上下文。

### 配置（复用 `.env`）

```
TRANSLATE_BASE_URL=…   # 任意 OpenAI 兼容端点（DeepSeek/OpenAI/…）
TRANSLATE_API_KEY=…
TRANSLATE_MODEL=…
```

- 脚本用 Node 原生 `process.loadEnvFile()` 读取；`.env.example` 增补三项说明；缺配置时
  报错并给出照抄指引。

### 翻译规则

- frontmatter：翻译 `title`、`description`；原样复制 `date`、`authors`、`order`、`image`、
  `draft`、`tags`（tags 是跨内容类型共享分类法，暂不翻译，待标签板块 i18n 时统一）；
  新增 `aiTranslated: true`。
- 正文保结构翻译：
  - 代码块与行内代码原样保留，不翻译代码内容；
  - 数学公式 `$…$` / `$$…$$` 原样保留；
  - `:::note[标题]` callout 保留指令名与 `{closed}` 标记，仅翻译文本；
  - `` `code{:ts}` `` 行内高亮语法保留；
  - 自定义 HTML 元素保留标签与属性、只译文本节点；`<style>` 块不译；
  - 链接 URL 不变、链接文本翻译；图片引用不变（同目录资产共用）。
- 提示词：系统规则清单 + "仅输出译文 Markdown"（不包裹代码围栏）+ 一个含 callout
  与行内代码的短示例示范格式服从；长文按 `##` 边界分块（约 6000 字符阈值），逐块携带
  术语提示与已译上下文后拼接；输出截断（`finish_reason=length`）时自动续写或细分块重试。
- 术语一致：同篇（及同系列）共享术语提示与已译上下文；不做术语表文件。

### 结构校验（写盘前自动执行）

- 比对源文与译文：代码块数量与语言、`:::` 块数量与类型、公式数量、行内代码数量、
  图片引用集合、链接 URL 集合、frontmatter 必填字段。
- 通过 → 写入 `X.en.md`，打印 token 用量与 `git diff` 审校提示。
- 不通过 → **不写内容目录**；译文与差异清单存到 `.translate/`（加入 `.gitignore`），
  退出码非 0。宁可不落盘，也不让半成品混进内容。

### 失败处理与审校

- 429/5xx/网络错误：指数退避重试（最多 3 次）；API key 无效立即失败并给指引。
- 无 draft 门禁——`git diff` 即审校环节；翻译中的 en 文件可标 `draft: true`，列表按
  "未翻译"对待。

### 测试

- 复用 `scripts/tests/` 惯例，建议新增 `translate-check.sh`：本地 stub 模拟 OpenAI 响应，
  离线测文件发现、分块、校验器、跳过/覆盖逻辑；翻译质量靠手动真实翻译一篇短文核对。

## SEO 与输出

- canonical：每页自身（现状）；提示页例外（→ 中文原文）。
- 页面级 hreflang：`MetaPost`/`MetaPage` 输出 `hreflang="zh-CN"` / `hreflang="en"` /
  `x-default`（→ 中文页），仅在有真实对应页时输出；提示页不输出 alternates。
- sitemap：`@astrojs/sitemap` 配置
  `i18n: { defaultLocale: "zh", locales: { zh: "zh-CN", en: "en" } }`（已核实该包支持并
  自动配对同路径页对生成 hreflang）；现有 filter 适配 `/en` 前缀。已知取舍：提示页会被
  sitemap 收录（只能按 URL 过滤），因 canonical + noindex 实际影响小；进一步优化不在本期。
- RSS：新增 `src/pages/en/rss.xml.ts`（仅已翻译文章，链接 `/en/blog/<id>`）；zh RSS 不变。
- 404：保持现状单页。

## 验证

- 必过：`npm run format:check`、`npm run build`。
- 手动清单：
  - zh 回归：首页/博客/系列/RSS 与改造前一致（系列页、目录、锚点重点核对）；
  - en：`/en/`、`/en/blog`（含标记）、已翻译文章、提示页（noindex + canonical）、
    系列占位块、`/en/rss.xml`；
  - head：html lang、og:locale、canonical、hreflang（有/无译文两种情形）；
  - 切换器：显隐与双向跳转（无死路）。
- 脚本：离线自测 + 手动真实翻译一篇覆盖 callout/代码/公式/图片/链接的短文。
